# The dashboard

The [live dashboard](https://invariant.puglisij.com/) shows the factory at work. `invariant dashboard -repo OWNER/NAME` serves it on http://127.0.0.1:8484, beside the factory [the README](../README.md#use-it-on-your-repository) sets up. This page says what its cards show and keep, and what the private `/act` page adds.

## Reader evidence

Each modeled project's evidence card embeds the checked reader chart from CI's receipt archive and links to a script-free evidence page and standalone `image/svg+xml` image. The shared native Go renderer draws the complete chart and report: literal labels, verbatim locked rules, unavailable model actions, all hidden occurrences and view-rule IDs, separately defined counts, checked bounds and source/tool provenance. The image works without scripts or a browser renderer. Its page identifies the repository, full project path and receipt commit, keeps the locked wording readable as text, and includes the complete reader record. Neither adds a proof claim or changes the receipt's verdict or code assurance.

The loader reads the manifest, model, every sibling TLA+ include, saved view and lock at the receipt commit, never a newer branch tip. It checks source hashes, reader and verification fingerprints, statement pins, bounds, completed model counts and tools against the report. Archived `reader.json` must equal the receipt's reader record and archived `reader.svg` must equal the shared renderer's output. The server serves that freshly rendered output, never arbitrary SVG from an archive. Ambiguous project basenames in the archive cannot supply reader charts for different full project paths.

Cards and evidence pages distinguish **no saved reader view**, legacy receipts, missing artifacts, snapshot mismatches, inconsistent companions and the receipt's generation-failure code. A project omitted from a partial receipt archive keeps its card and missing-report explanation, without a verification verdict, results or claimed provenance. Charts include **500 reachable concrete states**; a checked `too_large` record explains the actual count, the 500-state capacity and the bounds, without drawing a partial chart. A missing view remains a missing-view explanation even for a large model. The 20-arrow target is advice. Plumbing cards have no reader presentation. Public reader responses include no private action data and cannot open `/act`.

Reader URLs and ETags bind the repository and full project path, receipt commit, exact reader inputs, lock, full receipt and displayed contents, SVG bytes and presentation format. The disk cache retains structured evidence and archive companions. Restart validates them again, renders with the current renderer and checks the resulting identity against the saved card; incompatible or damaged entries become visible diagnostics, never dangling chart cards. Each project's evidence is restored independently for the next refresh. If any project evidence is damaged, the saved whole-page snapshot is discarded until a refresh can recompute its totals; a failed refresh retains the healthy project sources and the damaged project's diagnostic. If the archive is absent or expired and no previous evidence exists, discovered modeled projects get missing-artifact cards and pages without verification results. Existing evidence remains visible when a newer archive is unavailable. Missing archives and damaged caches retry even when the gate run has not changed, including after restart. Entries from repositories outside the configured set are not served. These immutable reader URLs are independent of the raw graph cache.

**Raw state graph detail** remains a separately labeled view with its existing exploration/edge coverage and traces. It may compact graph display data; neither reader charts nor claims about unavailable actions are reconstructed from `Graph.Compact`. The [example inventory and validation command](statecharts.md#example-inventory) cover all ten examples and all nine qualifying siblings.

This presentation implements [#631's ratified plan](../.invariant/plans/issue-631.json), on [D-0343](../decisions/journal/D-0343.jsonl), [D-0347](../decisions/journal/D-0347.jsonl), [D-0349](../decisions/journal/D-0349.jsonl) and [D-0351](../decisions/journal/D-0351.jsonl). [D-0353](../decisions/journal/D-0353.jsonl) records the presentation and cache policy.

## Proposal comparisons

Modeled proposal cards on both public and authenticated pages retain the complete checked `waiting.proposal` and its `waiting.reader` presentation. [Revision comparisons](statecharts.md#proposal-comparisons) show the complete candidate and named baseline, both exact model/include/view/lock identities, additions and removals, changed memberships and occurrence multisets before hiding. View changes, model-source changes and differing checking scopes are explicit. New projects compare to the immediately preceding selected proposal; amendments keep the captured ratified project even after the branch moves. Equal charts never establish behavioral equivalence.

Public script-free evidence pages and native SVG use the same checked record, with green added and red dashed removed states and arrows and a visible legend. Receipt pages retain the proposal comparison from `.invariant/comparison.json` beside the final-model sources and recomputed chart, so a synthesized model cannot relabel proposal evidence. Explicit size limitations stay visible and never imply empty graphs. Comparison data adds no verification verdict or assurance.

Proposal comparison URLs and ETags bind repository, issue, both retained source snapshots, complete comparison contents, presentation format and rendered bytes. The disk cache stores structured evidence. Restart revalidates source/delta fingerprints, the saved proposal and the immutable presentation identity before restoring an image. Damaged or missing proposal evidence becomes a visible diagnostic with no chart URL; healthy proposals keep their identities. Receipt comparison recovery follows the existing project evidence policy, including whole-snapshot rejection on damaged project sources. Restore a saved checked proposal or check the draft again; repair receipt comparisons at their captured project and reverify. Nothing silently reads a moving baseline branch or serves agent-supplied SVG.

This implements [#648's ratified plan](../.invariant/plans/issue-648.json) using the existing native rendering, receipt and cache policies. The merger records the new comparison and baseline policy decision and runs the [pinned-TLC comparison coverage](statecharts.md#proposal-comparisons) when Docker is unavailable to the builder; applicable real Python and TLAPS CI suites remain required.

## Modeled decisions

The modeled decision view shows all alternatives together, each with its exact option words, checked chart or explicit size/repair diagnostic, and immutable links to a script-free evidence page and native standalone SVG. Each choice retains the complete [preview snapshot](statecharts.md#modeled-alternatives) and its reader presentation in the state JSON. Pages show candidate rules, prior choices, checked bounds, full source/receipt/reader data and pinned tool provenance. They identify the repository, issue, fork and option and label every alternative unratified and model-only; no preview offers ratification or claims code assurance.

Preview cache identities bind repository, issue, containing fork and option IDs and words, exact model/includes/view, effective prior choices, diagnostics, receipts, tools, presentation format and rendered contents. ETags and immutable reader URLs change with any of those inputs. The server renders the checked structure with the shared Go renderer and never serves agent-supplied SVG.

Restart restores and revalidates each option separately from project receipts. A swapped snapshot, changed source, missing cache record or corrupted option gets its own diagnostic page and no image. Healthy siblings retain their evidence and stable conditional responses, including through another restart. Partial answers hide only the answered questions and keep the remaining snapshots' original choice context until another draft is checked. This separate option recovery preserves the existing project policy: damaged project evidence discards the saved whole-page snapshot until a refresh can recompute totals. Plumbing, PRD and authenticated D-0328 step-fit questions have no charts.

This behavior implements [#639's ratified plan](../.invariant/plans/issue-639.json) on D-0002, D-0307, D-0328, D-0345, D-0347, D-0351 and D-0353. D-0355 records the option-preview and cache policy, and the merger runs the [pinned-TLC integration](statecharts.md#modeled-alternatives) when Docker is unavailable to the builder.

## Factory activity

The live dashboard gives each running step its own card, with its activity, tool calls and stretches of thinking. A running Codex card with no completed reasoning item and no `turn.completed` event shows **Pending**, with the explanation "reported when the run ends" (`thinkingPending` in the live JSON), without a numeric thinking count or numeric thinking legend. A completed reasoning item clears Pending and shows the existing estimate from reasoning length, including a zero estimate. A whole `turn.completed` event also clears Pending; absent reasoning usage leaves the current total unchanged, and any estimate remains an estimate. Pending also clears when the agent or step ends ([D-0295](../decisions/journal/D-0295.jsonl)).

A Codex card's thinking total sums the `usage.reasoning_output_tokens` reported by completed turns, counting each whole transcript line once. The first reported count, including zero, replaces any estimates. The thinking statistic and total legend then show full integers without an approximation sign (`thinkingExact` in the live JSON). During later turns the total stays at the last reported sum while the card shows the current activity; refreshes and the end of the step retain that sum.

Reasoning items still appear as timed thinking stretches with their own estimated tokens, and later items don't inflate a reported total. Once reasoning or completion clears Pending, later turns or agent sessions in that transcript never restore it; neither do refreshes, rereads or trimmed timeline marks. Each card keeps its own counts and pending state, and a replaced transcript starts fresh. Claude Code keeps accumulating its streamed estimates without Pending. The public view publishes counts, times and paths inside the agent's copy only, never commands, agent words, output or reasoning text ([D-0051](../decisions/journal/D-0051.jsonl), [D-0116](../decisions/journal/D-0116.jsonl), [D-0136](../decisions/journal/D-0136.jsonl), [D-0159](../decisions/journal/D-0159.jsonl), [D-0160](../decisions/journal/D-0160.jsonl)).

The watcher gives every draft or build invocation its own directory, including retries within the same second, and publishes its basename in the step's status as `run` after creating it and before starting the agent. The activity strip and banner checks read only that named run under the selected watcher and issue. A new step starts without a run; an absent run, directory or required file shows no activity or checks from an earlier run. Directory names are opaque identities, so their timestamps, sort order and modification times never select a run ([D-0166](../decisions/journal/D-0166.jsonl)).

When a draft's or build's step ends, however it ended, the watcher records when, in its status file, with the step's start, run, agent and the time limit its agent ran under, apart from the steps it's running. It keeps the steps that ended last, and every one that ended at that same moment, through heartbeats, restarts and its own shutdown, until a later one ends. Once none of a repository's steps is running, those are its cards, whether or not a page was open when they ended and whether or not the dashboard has restarted since: the latest end any of the repository's watchers recorded, running or stopped, in whatever order their work directories come, each tie read from its own watcher's run. Running cards still follow the lease holder or the working watcher. A finished card stops at its recorded end and keeps its run's checks, and its heading says only that the step ended, as `Build step ended`, since the attempt may have stopped or failed. A step that just disappears, a transcript or a page read never supplies an end, and a step that starts on the same issue still has no run until its own directory exists.

Every watcher's drafts and builds also keep their agent's public activity, the counts, times, tool kinds and paths inside its copy that the card shows, in the run's `activity.json`. The watcher reads each whole event as the agent's backend writes it, with the live view's own checks, while the workspace still holds what it names, and saves what it has read each time a run returns, however it ended, before the workspace is cleaned up. Events from a fallback, or from a plumbing build's repairs, add to it, each once, and deleting or renaming files can't take back what earlier events showed. Events as large as the agents' readers take, 64 MiB, count like any other, and a review, which only reads, writes a transcript of its own and never touches it. So a finished card keeps its file paths and sizes after the workspace is gone, without a page having read the transcript; a run that saved nothing is read from its transcript as the live view reads it. Finished cards never show shell commands, even at `/act`. The live view, like the saved activity, counts a fallback's or repair's Codex items once, though each run of Codex numbers its items afresh. This is [#269's ratified plan](../.invariant/plans/issue-269.json). [D-0192](../decisions/journal/D-0192.jsonl) records its decision: watcher-recorded ends, @gitdek's choice of the latest finishers and the saved activity ([D-0051](../decisions/journal/D-0051.jsonl), [D-0116](../decisions/journal/D-0116.jsonl)).

At `/act`, behind Cloudflare Access, **Show shell commands** displays each running step's shell invocations verbatim beside its activity strip, with their existing kind and start/end times. It starts off on every page load. Turning it off, losing access, ending a step or replacing its run clears the display, and a late response cannot restore it. Commands are inert text, with no tool output or reasoning, and retained only for the strip's bounded recent window. Only an authenticated `GET /act/api/live.json?commands=1` includes them, with `Cache-Control: no-store`; the default private response, public responses and agent listener never include command text. This private view follows [#236's ratified plan](../.invariant/plans/issue-236.json), an exception to [D-0116](../decisions/journal/D-0116.jsonl) for this page only ([D-0165](../decisions/journal/D-0165.jsonl)), behind the existing [Access boundary](../decisions/journal/D-0065.jsonl).
